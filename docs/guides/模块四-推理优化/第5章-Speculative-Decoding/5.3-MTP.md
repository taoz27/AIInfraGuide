5.2 的 EAGLE-3 走的是"为推理专门训练一个草稿"的路线：Base 模型训练完成后，再花一份算力去训练草稿。MTP（Multi-Token Prediction）把顺序倒了过来——它是**训练侧的设计**，推理加速更像是顺带的红利。这是 DeepSeek-V3 引入并带火的结构：主模型在训练时就附带一个多 Token 预测头，等到部署推理时，这个头直接被拉来当草稿用，一石二鸟。

本节讲清三件事：MTP 的结构和它**训练优先**的设计动机；它在推理阶段的草稿形态——**线性无分支**的草稿序列；以及一个有趣的工程现实——**理论上可以有多个 MTP 头，但现实里无论模型还是引擎都只支持一个**。

## 1. MTP 是什么：主模型自带的多 Token 预测头

### 1.1 结构：主模型 + 一个 MTP 头

DeepSeek-V3 的 MTP 结构很简洁：

- **主模型照常训练**：正常做下一 Token 预测（1-token objective）；
- **额外挂一个 MTP 头**：一个轻量模块——一个 Transformer 块，共享主模型的 Embedding，配一个输出投影。它拿主模型对第 $D$ 个 Token 的隐层表征，**跳跃预测第 $D+1$ 个 Token**（即往前多看一步）。

```mermaid
graph LR
    subgraph Main["主模型（正常训练）"]
        A["输入 ...T_{D-1}"] --> B["隐层表征 h_D"]
    end
    B -->|"投影 + 拼接上下文"| M["MTP 头<br/>（一个 Transformer 块）"]
    M --> P["预测 T_{D+1}<br/>（往前多看一步）"]
```

关键特征：**没有单独的草稿模型**——MTP 头的权重就住在主模型的 checkpoint 里，与主模型联合训练，天然同源（同一个 Embedding、同一份训练数据、同一次优化过程）。

### 1.2 理论上可以堆叠，现实里只有一个

按论文的递归设计，MTP 头是**可以堆叠的**：第 1 个头预测 $T_{D+1}$，第 2 个头拿第 1 个头的输出再预测 $T_{D+2}$……理论上 $N$ 个头就能在一次前向里多看 $N$ 步。但无论理论多美好，现实非常骨感：

- **模型侧**：DeepSeek-V3 发布时只带了**一个** MTP 头；
- **引擎侧**：vLLM、SGLang 的实现同样只支持一个 MTP 头。

为什么停在 1 个？直觉上的权衡是：头的数量每加一，训练开销和显存占用都在涨，而越远的 Token 越难预测，边际收益快速递减；一次前向内预测 2 步之外的部分，训练信号也越稀薄。单头"往前看一步"配合推理时的自回归展开（第 3 节），已经是性价比最高的形态。

## 2. 设计动机：训练视角的优先级

### 2.1 MTP 首先是训练优化

从论文的叙述看，MTP 的第一身份是**训练技术**：让模型在每个位置都多预测一步，等于给训练加了**更密的监督信号**——主模型不再只学"下一个 Token"，还要学"下下个 Token"，这能提升训练的数据效率和模型质量（DeepSeek-V3 论文中 MTP 属于"改进训练"的章节，多 Token 的训练收益才是论述重点）。

换句话说，理解 MTP 的正确顺序是：**它最初考虑的是训练上的优化，投机采样是它在推理阶段的一个附加收益**。头是训练时练出来的，推理时发现这个头"顺便"能当草稿用——于是白拿了一份加速。

用一个类比：MTP 头像训练时安排的"陪练位"——训练时它逼着主模型把"往后多看几步"的能力显式练出来（训练收益）；比赛（推理）时，这个陪练直接下场当草稿选手（推理收益）。一份投入，两份回报。

### 2.2 与"为推理训练草稿"路线的对照

| 📊 维度 | EAGLE-3 路线 | MTP 路线 |
|---|---|---|
| 草稿从哪来 | Base 训练完，**专门训练**草稿 | 与主模型**联合训练**，附带产出 |
| 额外训练成本 | 需要一份单独的训练流程 | 打包进主模型训练，边际成本低 |
| 草稿与 Base 的同源性 | 靠特征喂入 + 蒸馏对齐 | 天然同源（同 Embedding、同数据） |
| 生态依赖 | 需要社区/自己训草稿权重 | 模型发布自带，开箱即用 |

对模型厂商（如 DeepSeek）而言，MTP 把"要不要投采优化"的决策从推理团队前移到了训练团队——训练时多花一点成本，下游所有用户都能白拿推理加速，这是它作为平台级设计的吸引力。

## 3. 推理形态：线性无分支的草稿序列

### 3.1 草稿展开：一个头的自回归复用

推理时，单个 MTP 头怎么给出多个草稿 Token？答案是**把头当小模型自回归地跑**：

1. 拿当前已确认的上下文，MTP 头预测出 $T_2'$（草稿 1）；
2. 把 $T_2'$ 当作"已生成"追加进上下文，MTP 头再跑一次，预测 $T_3'$；
3. 如此往复，展开出 $T_2' \sim T_{k+1}'$ 的草稿序列；
4. 送 Base 验证——流程与 5.1 节的通用框架完全一致。

所以 MTP 的草稿形态是**线性无分支的草稿序列**：一条链，没有 EAGLE-3 那种 top-k 的树状展开。每一步只有一个候选，一步猜错全链报废。

### 3.2 优劣：同源性 vs 无容错

**优势**在与主模型的深度同源：MTP 头见过主模型全部训练数据的监督，草稿分布与主模型对齐得非常好，单步接受率高；而且不需要额外部署一个模型，权重、Tokenizer、服务链路全部复用主模型的。

**劣势**正是"线性"：没有分支容错，接受长度被 5.1 节讲的连乘概率死死压住。单头自回归展开的每一步都是"押注 top-1"，押错一次整轮提前结束。这也是它接受长度上限不如树状草稿的原因。

📌 **关键点**：接受策略上，DeepSeek-V3 论文明确说 MTP 的投机推理采用**类似 Medusa 的典型接受方案**——不追求严格的 Rejection Sampling 修正，而是按置信度决定接受前缀（实践中以贪婪/典型接受为主流配置）。实现细节各引擎略有差异，但"Base 验证、按前缀接受"的骨架不变。

## 4. 工程现实：一个头与引擎支持

### 4.1 引擎中的 MTP：当 EAGLE 用

各引擎对 MTP 的落地高度一致——**把 MTP 头当作一个 EAGLE 式的草稿模型来用**：

- **vLLM / SGLang**：在投机解码配置里指定 MTP 权重（DeepSeek 系列 checkpoint 自带），草稿长度等参数照常设置，验证走统一的投机解码框架。两者当前都只支持单个 MTP 头；
- **TensorRT-LLM**：做得更"物理"一些——**把 MTP 头从主模型里拆出来，变成一个独立的草稿模型**，与 EAGLE-3 草稿一视同仁地部署。主模型归主模型，草稿归草稿，调度上更干净。

这个"拆出来"的视角很有启发：**MTP 与 EAGLE-3 在推理系统眼里，终究是同一种东西**——一个挂在 Base 旁边的轻量草稿结构。区别只在草稿是"训练时顺带练出来的"（MTP）还是"事后专门训练的"（EAGLE-3）。

### 4.2 生产基线：MTP-1

值得一提的定位：DeepSeek 的生产服务系统以**单头 MTP（MTP-1）作为投机解码的生产基线**——5.5 节的 DSpark 论文里，所有收益都对比这个基线报告（相同吞吐下单用户速度 +60%~85%）。换句话说，MTP-1 是当前"模型自带草稿"路线的代表刻度尺。

### 4.3 后续演进：FastMTP 等

MTP 的一个后续优化方向与 EAGLE-3 的 Training-Time Test 呼应：FastMTP 等工作指出，MTP 训练时的输入是"标准答案上下文"，而推理时它的输入是"自己猜的上下文"，两者存在分布错位——修法同样是**让训练对齐推理时的真实使用模式**，进一步提升草稿质量。这类"训练-推理对齐"已经成为草稿模型训练的通用方法论。

## 📝 总结

- MTP 是 DeepSeek-V3 引入的**训练侧设计**：主模型训练时附带一个多 Token 预测头（一个 Transformer 块，共享 Embedding），提供更密的训练信号——**投采是它在推理阶段的附加收益**，不是它被发明的第一动机。
- 结构上**没有单独的草稿模型**：MTP 头权重在主模型 checkpoint 里、与主模型联合训练，天然同源；理论上头可堆叠（多个头各看一步），**现实中模型与 vLLM/SGLang 都只支持一个头**。
- 推理形态是**线性无分支草稿**：单头自回归复用展开 $T_2' \sim T_{k+1}'$，接受策略类似 Medusa 的典型接受。优势是单步接受率高、零额外部署；劣势是无分支容错，接受长度受连乘压制。
- 引擎落地：vLLM/SGLang 把 MTP 头当 EAGLE 式草稿用；TensorRT-LLM 更进一步**把 MTP 头拆成独立草稿模型**，与 EAGLE-3 同等对待。
- 生产定位：MTP-1 是 DeepSeek 生产系统的投机解码基线，也是 5.5 节 DSpark 的对比锚点。
